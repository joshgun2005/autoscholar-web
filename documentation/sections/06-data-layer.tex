\chapter{Data and Storage Architecture}
\label{ch:data-layer}

\section{Overview}
\label{sec:data:overview}

\autoscholar's data architecture spans three distinct layers: (1) \textbf{external data acquisition} from 15+ API providers, (2) \textbf{transient computational data} flowing through Python subprocesses, and (3) \textbf{persistent storage} in SQLite or PostgreSQL via Drizzle ORM.
This chapter documents each layer in detail.

\subsubsection{EODHD (End of Day Historical Data)}

\file{eodhd\_service.ts} (289 lines) provides extended historical coverage:

\begin{itemize}
  \item \textbf{End-of-day prices:} US stocks back to IPO date, non-US from 2000. OHLCV with adjusted close.
  \item \textbf{Intraday data:} 1-minute, 5-minute, 1-hour bars with pre/after-market data.
  \item \textbf{Options chains:} US options for 6,000+ stocks with end-of-day Greeks ($\delta$, $\gamma$, $\theta$, $\nu$).
  \item \textbf{Live quotes:} Real-time price data.
\end{itemize}

Key implementation details:
\begin{itemize}
  \item Auto-normalizes bare tickers to \texttt{.US} suffix format.
  \item Accepts flexible date inputs (Unix timestamps, ISO strings, datetime objects).
  \item Sanitizes null/NaN values in options data.
\end{itemize}

\subsubsection{Financial Data API (Real Options)}

\file{financialDataService.ts} (295 lines) provides real-time options market data:

\begin{itemize}
  \item \textbf{Option chains:} All available contracts (calls and puts) with identifiers.
  \item \textbf{Option prices:} Last price, bid/ask, volume, open interest, implied volatility, intrinsic/time value.
  \item \textbf{Option Greeks:} Delta ($\delta$), Gamma ($\gamma$), Theta ($\theta$), Vega ($\nu$), Rho ($\rho$), plus implied volatility.
\end{itemize}

All functions validate the OCC identifier format: \texttt{SYMBOL+YYMMDD+C/P+Strike$\times$1000}.

\subsection{Macroeconomic Data}

\subsubsection{FRED (Federal Reserve Economic Data)}

Accessed via the Python client \file{fred\_client.py} (135 lines) and JavaScript service:

\begin{itemize}
  \item 840,000+ macroeconomic time series.
  \item Unit transformations (change, percent change, log).
  \item Frequency aggregation (daily, weekly, monthly, quarterly, annual).
  \item Series search with tag filtering and sort options.
  \item Category navigation and release tracking.
\end{itemize}

\subsubsection{World Bank}

\file{worldBankService.ts} (130 lines), no API key required:

\begin{itemize}
  \item 16,000+ development indicators across 200+ countries.
  \item Metadata: countries with income/region filtering, topics, regions, income levels, data sources.
  \item Client-side keyword search (WB API v2 lacks native search).
  \item Data retrieval with date ranges, frequency, and source filtering.
\end{itemize}

\subsubsection{IMF (International Monetary Fund)}

\file{imfService.ts} (93 lines), dual-interface:

\begin{description}
  \item[DataMapper API:] Simple access to WEO macroeconomic indicators (GDP growth, inflation, unemployment).
  \item[SDMX 3.0 API:] Advanced multi-dimensional queries across CPI, IFS, BOP, and other datasets. CSV output.
\end{description}

\subsubsection{OECD}

\file{oecdService.ts} (99 lines), no API key required:

\begin{itemize}
  \item 1,475+ SDMX dataflows covering economics, health, education, environment.
  \item Dot-separated dimension filters with CSV-with-labels output.
  \item Dimension structure and codelist discovery.
  \item Client-side keyword search across all dataflows.
\end{itemize}

\subsubsection{Data Flow Through Python}

\begin{enumerate}
  \item Claude writes Python code via the \texttt{execute\_custom\_python\_analysis} tool.
  \item The TypeScript bridge (\file{customPython.ts}) applies automatic patches and spawns the Python subprocess.
  \item Python code receives context via JSON stdin (API keys, session ID, previous outputs).
  \item The code executes with access to all pre-loaded clients and databases.
  \item Results are returned as structured JSON: figures (base64), files (paths), stdout text, and errors.
  \item The ScriptManager saves the script for potential repair iterations.
\end{enumerate}

\section{Persistent Storage}
\label{sec:data:persistent}

\subsection{Database Schema}

The database schema (\file{shared/schema-sqlite.ts}, 456 lines; \file{shared/schema.ts}, 357 lines) defines 20+ tables:

\subsubsection{User and Authentication Tables}

\begin{description}
  \item[\texttt{users}] --- User accounts with username, email, hashed password, display name, institution, department, ORCID, API key, role, and token.
  \item[\texttt{userProfiles}] --- Extended user profile information.
  \item[\texttt{emailVerificationTokens}] --- Email verification token tracking.
  \item[\texttt{passwordResetTokens}] --- Password reset token tracking.
\end{description}

\subsubsection{Content Tables}

\begin{description}
  \item[\texttt{messages}] --- Chat messages with session ID, role, content, serialized sources, and timestamps.
  \item[\texttt{sharedReports}] --- Published research reports with share IDs, questions, answers, sources, tool results, and figures.
  \item[\texttt{crawledPages}] --- Web page content for indexing.
  \item[\texttt{embeddings}] --- Vector embeddings for semantic search (stored as JSON text in SQLite, native vector in PostgreSQL).
\end{description}

\subsubsection{Research Output Tables}

\begin{description}
  \item[\texttt{publishedPapers}] --- Published papers with title, abstract, domain, template, \LaTeX{} sections (JSON), BibTeX, figure/word/section/line counts, peer review score, project ZIP path, ASID, visibility, and timestamps.
  \item[\texttt{peerReviews}] --- AI peer review results with scores, recommendation, strengths, weaknesses, detailed scores (JSON), section reviews (JSON), and full report text.
  \item[\texttt{savedPrompts}] --- Public prompt library entries.
\end{description}

\subsubsection{Pipeline Management Tables}

\begin{description}
  \item[\texttt{paperRuns}] --- Pipeline run tracking with status, prompt, session ID, heartbeat, Popper score, governor state (serialized JSON), timestamps.
  \item[\texttt{governorDecisions}] --- Individual governor decision records with run ID, stage, trigger, action, reasoning, confidence.
  \item[\texttt{asidCounters}] --- Atomic counters for ASID generation, keyed by year.
\end{description}

\subsubsection{Analytics Tables}

\begin{description}
  \item[\texttt{conversationSessions}] --- Session metadata with user ID, session ID, title, message count, token usage, cost, and timestamps.
  \item[\texttt{activeUsers}] --- Heartbeat-based active user tracking with 2-minute activity window.
  \item[\texttt{analyticsMetrics}] --- Time-series platform metrics (requests, users, performance, tokens, errors).
  \item[\texttt{requestLogs}] --- API request audit log with method, path, status, duration, user agent.
\end{description}

\subsubsection{Administrative Tables}

\begin{description}
  \item[\texttt{siteConfig}] --- Key-value configuration store with upsert semantics.
  \item[\texttt{donations}] --- Crypto and fiat donation records.
  \item[\texttt{apiKeys}] --- Public API keys with SHA-256 hashing, scopes, rate limits, usage tracking.
\end{description}

\subsection{Storage Layer Implementation}

The storage layer is decomposed into 6 domain-specific modules that are composed into a single \texttt{IStorage} interface (70+ methods):

\begin{description}
  \item[\file{user-storage.ts}] (49 lines) --- CRUD with cascading session deletion.
  \item[\file{message-storage.ts}] (64 lines) --- Messages and shared reports.
  \item[\file{session-storage.ts}] (78 lines) --- Session lifecycle management.
  \item[\file{paper-storage.ts}] (232 lines) --- Papers, pipeline runs, cost calculation ($5/\$25$ per MTok for Opus 4.6).
  \item[\file{analytics-storage.ts}] (117 lines) --- Active users, metrics, request logs.
  \item[\file{admin-storage.ts}] (167 lines) --- Governor state, reviews, donations, API keys, site config.
\end{description}

\subsection{Database Migrations}

For SQLite, migrations are performed inline in \file{db.ts} (241 lines) via safe \texttt{ALTER TABLE} statements.
Each migration:
\begin{enumerate}
  \item Checks if the column exists using \texttt{PRAGMA table\_info}.
  \item Adds the column if missing.
  \item Seeds default data where needed (e.g., initial donation records).
\end{enumerate}

For PostgreSQL, Drizzle's \texttt{db:push} command handles schema synchronization.

\section{Data Lifecycle}
\label{sec:data:lifecycle}

\begin{enumerate}
  \item \textbf{Acquisition:} External APIs $\to$ JSON responses $\to$ tool results in Claude context.
  \item \textbf{Processing:} Python subprocesses load, clean, merge, and analyze data.
  \item \textbf{Intermediate storage:} CSV/JSON files in \texttt{downloads/}, figures in \texttt{public/plots/}.
  \item \textbf{Paper integration:} Data summaries embedded in \LaTeX{} sections, figures referenced.
  \item \textbf{Packaging:} All artifacts bundled into the reproducible project ZIP.
  \item \textbf{Publication:} Paper metadata and ZIP path stored in the database.
  \item \textbf{Access:} Papers accessible via web UI, REST API, and repository browser.
\end{enumerate}
